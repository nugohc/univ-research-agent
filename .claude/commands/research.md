# 리서치 파이프라인 실행

조사 주제: **$ARGUMENTS** (비어 있으면 "타대학 장학 제도"로 진행)

아래 절차를 순서대로 수행하라.

## 0. 준비
1. `agent-browser --version`으로 agent-browser CLI가 설치되어 있는지 확인한다. 없으면 `npm install -g agent-browser && agent-browser install`로 설치한다.
2. 오늘 날짜로 산출물 폴더를 만든다: `research\<YYYY-MM-DD>\` (프로젝트 루트 기준). 이미 있으면 그대로 사용한다.

## 1. 조사원 동시 실행 (반드시 5개를 한 메시지에서 병렬 실행)
Agent 도구 호출 5건을 **하나의 메시지에 모두 담아** 동시에 실행한다. 순차 실행 금지.

| 조사원 | subagent_type | 세션명 | 결과 파일 |
|---|---|---|---|
| 정책 조사원 | `policy-researcher` | `policy` | `research\<날짜>\01_정책조사.md` |
| 타대학 조사원(거점국립대) | `univ-researcher` | `univ-national` | `research\<날짜>\02_타대학_거점국립대.md` |
| 타대학 조사원(주요 사립대) | `univ-researcher` | `univ-private` | `research\<날짜>\03_타대학_주요사립대.md` |
| 타대학 조사원(특수대학) | `univ-researcher` | `univ-special` | `research\<날짜>\04_타대학_특수대학.md` |
| 공시 조사원 | `disclosure-researcher` | `disclosure` | `research\<날짜>\05_공시조사.md` |

각 프롬프트에 반드시 포함할 것:
- 조사 주제
- agent-browser 세션명 (위 표의 값 — 병렬 실행 충돌 방지)
- 결과 md 파일의 **절대 경로**
- 조사 시간 15분 제한 리마인드
- 타대학 조사원에게는 담당 대학군(거점국립대 / 주요 사립대 / 특수대학) 명시

5개 결과가 모두 돌아올 때까지 기다린다. 일부가 실패하면 실패 사실을 기록하고 성공한 결과만으로 진행한다.

## 2. 편집장 초안
`chief-editor` 서브 에이전트를 실행해 다음을 전달한다:
- 조사 결과 md 파일들의 절대 경로 목록
- 최종안 저장 경로: `research\<날짜>\10_보고서_목차_스토리라인.md`
- 지금은 1단계(논의용 초안)만 수행하라는 지시

## 3. 사용자와 논의 (생략 금지)
편집장의 초안(반드시 언급할 점 / 언급하되 가릴 점 / 스토리라인 대안 / 질문)을 사용자에게 그대로 보여주고, AskUserQuestion 또는 대화로 사용자의 결정을 받는다.
받은 피드백은 SendMessage로 **같은 편집장 에이전트에게** 전달해 수정안을 받는다. 사용자가 확정할 때까지 반복한다.

## 4. 확정 및 저장
사용자가 확정하면 편집장에게 최종 저장을 지시하고, 저장된 `10_보고서_목차_스토리라인.md` 경로와 최종 목차 요약을 사용자에게 보고한다.

## 5. 보고서 v1 작성
편집장에게 확정된 목차·스토리라인(`10_보고서_목차_스토리라인.md`)대로 보고서 본문을 작성하게 한다.
- 저장: `research\<날짜>\보고서_v1.md`
- 조사 파일에 없는 내용 금지, 수치마다 출처 명기, 민감 수치 처리 원칙 적용을 프롬프트에 포함한다.

## 6. 감사-수정 루프 (최대 3회 왕복)
`auditor` 서브 에이전트의 정의 파일에 적힌 평가 기준 8개와 멈추는 조건을 따른다.

각 회차 N(1부터):
1. **감사**: `auditor`에게 `보고서_vN.md`와 근거 자료(01~05, 10) 경로를 주고 검토시킨다. 결과: `research\<날짜>\검토의견_N회차.md`
2. **판정 확인**: 지적 0건이면 적합 판정 — 루프 조기 종료.
3. **수정**: 편집장에게 검토의견을 전달해(가능하면 SendMessage로 같은 편집장에게) 다음 버전 `보고서_v(N+1).md`를 쓰게 한다. 이전 버전 파일은 덮어쓰지 않는다 — 회차마다 별도 파일.
4. **커밋·푸시**: 회차가 끝날 때마다 검토의견과 새 보고서 버전을 git 커밋하고 GitHub에 푸시한다. (커밋 메시지에 회차와 지적 건수 명기)
5. N=3이면 잔여 지적이 있어도 종료한다.

## 7. 버전 비교 정리
보고서 버전들을 나란히 비교해 회차별로 무엇이 달라졌는지 `research\<날짜>\버전_비교.md`로 정리하고 사용자에게 보고한다.

## 8. HWPX 출력
최종 보고서가 확정되면 `pnu-hwpx-report` 스킬로 한글(hwpx) 보고서를 출력한다.

## 주의
- 조사원이 저장한 md 파일을 메인 에이전트가 임의로 고쳐 쓰지 않는다.
- 감사 담당은 보고서를 직접 고치지 않는다. 수정은 항상 편집장이 한다.
- `pnu-hwpx-report` 스킬 파일 자체는 수정하지 않는다(출력 용도로만 사용).
